# 배포와 운영

## 정적 배포

현재 설정은 `output: "export"`, `trailingSlash: true`, `images.unoptimized: true`입니다. 런타임 Next 서버 없이 HTML·CSS·JavaScript를 제공하는 방식입니다.

```sh
npm ci
npm test
npm run lint:studio
npm run build
npm run typecheck
```

배포할 디렉터리는 **out**입니다. 배포 서비스에는 빌드 명령 `npm run build`, 출력 경로 `out`, Node 24.14.0을 설정합니다. 환경 변수나 앱 비밀 키는 없습니다.

`npm start`는 127.0.0.1에서만 제공하는 로컬 확인 서버입니다. 공개 웹 서버나 프로세스 관리 도구로 사용하지 않습니다.

## 경로와 호스팅 확인

- 사이트 루트에서 `/`, `/studio/`, `/view/`, `/legacy/`를 직접 열 수 있어야 합니다.
- 각 디렉터리의 `index.html`을 제공하고 `_next/` 정적 파일을 같은 배포에 포함합니다.
- 현재 코드는 사이트 루트 배포를 기준으로 합니다. GitHub 저장소 업로드와 GitHub Pages 배포는 별개입니다.
- `/repository-name/` 같은 하위 경로에 올리려면 Next basePath뿐 아니라 앱의 절대 경로·공유 URL·썸네일 경로를 함께 점검해야 합니다. 이 패키지는 GitHub Pages 하위 경로 배포가 검증된 상태가 아닙니다.
- HTTPS를 사용하고 공유 링크, 클립보드, PNG와 ZIP 다운로드를 확인합니다.
- 설치와 빌드 과정에서는 npm 및 Google Fonts에 대한 네트워크 접근이 필요합니다.

이 업로드 패키지에는 원래 운영 중인 호스팅의 프로젝트 식별자와 배포 전용 스크립트를 포함하지 않습니다. 자신의 호스팅 환경을 연결하세요.

## 배포 확인

1. 같은 소스와 lockfile로 검사를 통과한 정적 결과물을 배포합니다.
2. 호스팅의 완료 상태와 실제 배포 URL을 기록합니다.
3. 빈 브라우저에서 프리셋 생성·수정·새로고침·JSON 내보내기를 확인합니다.
4. 공유 링크를 별도 브라우저에서 열고 사본 만들기를 확인합니다.
5. AI 전달 ZIP에 페이지별 기준 이미지와 명세가 포함되는지 확인합니다.

현재 GitHub Actions는 빌드·단위 검사·타입·현재 편집기 lint를 수행하며 자동 서비스 배포는 하지 않습니다.

## 업데이트·롤백

문서 스키마와 기존 JSON의 호환성을 먼저 검증합니다. 호스팅이 직전 버전을 보관하면 문제가 생겼을 때 해당 정적 배포를 복구합니다. 사이트를 되돌리는 것과 사용자의 브라우저 데이터를 복구하는 것은 별개입니다.

이전 앱이 최신 문서를 읽지 못할 수 있으므로 무조건적인 롤백 대신 호환성을 확인하세요. 장애 대응 목적으로 방문자의 저장소를 초기화하는 코드를 넣지 않습니다.

## 데이터와 운영 범위

프로젝트 데이터는 방문자 브라우저에 있습니다. 운영자가 서버 DB에서 사용자 프로젝트를 복원할 수 없습니다. 중요한 작업의 JSON 백업, 미저장 복구본 다운로드, 충돌 시 사본 저장을 안내합니다.

도메인을 변경하면 브라우저 저장 공간이 달라집니다. 기존 주소에서 백업할 수 있는 기간과 새 주소의 가져오기 방법을 안내하세요. 앱에는 원격 분석이나 오류 수집 SDK가 없습니다. 호스팅 접속 로그의 수집·보관 정책은 호스팅 운영 설정에 따릅니다.
