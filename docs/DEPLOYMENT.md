# 정적 배포

현재 설정은 `output: 'export'`, `trailingSlash: true`, 이미지 최적화 비활성화입니다. 배포 산출물은 `out/`이며 런타임 Next 서버와 프로젝트 데이터 서버를 사용하지 않습니다.

## 배포 흐름

```mermaid
flowchart LR
    Source[소스와 lockfile] --> Install[npm ci]
    Install --> Check[단위 · lint]
    Check --> Build[npm run build]
    Build --> Out[out/ 정적 파일]
    Out --> Local[npm start · 브라우저 확인]
    Local --> Host[도메인 루트의 정적 호스팅]
    Host --> Verify[경로 · 자산 · 저장 · 공유 확인]
```

```sh
npm ci
npm test
npm run lint:studio
npm run build
npm run typecheck
npm start
```

로컬에서 `http://127.0.0.1:3200`의 `/`, `/studio/`, `/view/`, `/legacy/`를 확인합니다. `npm start`의 서버는 로컬 검증용이며 사용자 공개 서버로 운영하지 않습니다.

## 호스팅 설정

| 항목             | 값                               |
| ---------------- | -------------------------------- |
| 설치 명령        | `npm ci`                         |
| 빌드 명령        | `npm run build`                  |
| 출력 디렉터리    | `out`                            |
| 환경 변수·API 키 | 없음                             |
| 경로 방식        | `/studio/` → `studio/index.html` |
| 권장 배치 위치   | 도메인 루트                      |

`out/` 내부의 모든 파일과 `_next/`, 미디어·서체·CSS를 함께 배포합니다. HTML은 갱신이 반영되도록 하고 해시가 포함된 `_next/static/` 자산은 호스팅의 캐시 정책을 적용합니다. 미디어·자막 파일은 서버가 실제 MIME 유형으로 제공하도록 확인합니다.

GitHub에 소스를 올리는 작업과 사이트를 공개 배포하는 작업은 별개입니다. 현재 소스에는 `/studio-ui.css`, `/studio-assets/` 같은 루트 경로가 있으므로 GitHub Pages의 `/repository/` 하위 경로에 그대로 올리면 자산 경로가 맞지 않을 수 있습니다. 해당 방식은 `basePath`와 모든 절대 경로를 함께 검토하고 별도로 검사해야 합니다. 이번 패키지는 특정 호스팅에 자동 게시하지 않습니다.

## 배포 확인

1. 새 브라우저에서 프로젝트 생성·편집·저장·새로고침을 확인합니다.
2. 390·768·1440px 미리보기, 이미지·영상·자막·서체를 확인합니다.
3. 자산 포함 ZIP 백업과 복원, AI 전달 ZIP 다운로드를 확인합니다.
4. 공유 링크를 별도 브라우저에서 열어 읽기와 사본 생성을 확인합니다.
5. 배포한 소스 revision과 산출물 버전을 기록합니다.

## 업데이트와 복구

같은 출처를 유지하면 브라우저 저장소를 계속 사용합니다. 도메인·프로토콜·포트가 달라지면 다른 저장 공간이 됩니다. 서비스 주소를 바꾸기 전에는 사용자가 자산 포함 ZIP으로 이동할 수 있게 안내하세요.

장애 시 이전에 검증한 정적 산출물을 재배포합니다. 브라우저 데이터는 별도이므로 이전 코드가 새 스키마를 읽을 수 있는지 확인합니다. 자동 변환은 이전 문서를 새 버전으로 읽는 방향이며 이전 앱이 v5를 읽을 수 있다고 가정하지 않습니다. 저장소 초기화보다 현재 작업의 백업과 사본 복원을 먼저 사용합니다.

기존 Sites 연결은 원본 작업 공간의 `.openai/hosting.json`에 있습니다. GitHub 업로드 패키지는 이 연결과 해당 게시 스크립트를 제외합니다. 기존 배포를 관리할 때는 원본 작업 공간을 사용합니다.
