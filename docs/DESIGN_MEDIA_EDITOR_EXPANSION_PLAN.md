# Prompt Studio 테마·미디어·편집 확장 계획

작성·조사일: 2026-10-07 (한국 시간). 상태: **조사 및 구현 계획 — 아래 신규 기능은 아직 구현하지 않았다.** 현재 작업 트리의 코드와 기존 구현 기록을 기준으로 작성했다. 이전 변경 사항은 보존한다.

목표는 **다양한 웹 디자인을 고르고, 이미지·영상·모션을 조합한 뒤, 내부 구조와 반응형까지 직접 바꿀 수 있는 편집기**다. 추천 방향은 기존 편집기를 확장하면서 디자인 팩, 미디어 자산, 구조 편집, 모션 편집을 같은 문서 모델로 연결하는 것이다.

이번 확장의 목표 규모는 디자인 팩 16종, 신규 기능 컴포넌트 20종, 기존 컴포넌트 개선 12종, 장면 블록 24종, 추가 모션 프리셋 12종이다. 수량은 구현 목표이며 완성도에 따라 조정한다. 첫 출시 범위는 이 가운데 **디자인 팩 8종·신규 기능 8종·장면 블록 12종**과 자산·편집 기반으로 제한한다.

## 3. 테마를 디자인 팩으로 확장

### 구성과 적용 방식

하나의 팩은 색상 토큰, 제목/본문/숫자 서체, 크기 체계, 간격, 표면·테두리·그림자, 장식 자산, 추천 장면, 모션 기본값, 모바일 대체 표현을 포함한다. 기존 12개 팔레트와 8개 외형은 계속 선택할 수 있게 한다. **16개 팩에는 기존 스타일의 재설계도 포함하며, 팔레트 수와 합산하지 않는다.**

사용자는 `전체 인상`, `색상`, `서체`, `표면`, `모션`을 선택해서 적용한다. 기존 페이지에 테마를 적용할 때 콘텐츠나 배치 트리를 바꾸지 않는다. 새로운 배치는 별도의 `이 장면 추가` 또는 `구조 바꾸기`에서 미리 본 뒤 적용한다. 개별 수정 유지가 기본값이고, 수정값 초기화는 영향을 받는 속성을 보여주는 별도 동작이다.

팩당 대표 페이지 1개와 핵심 블록 3개 이상에서 같은 인상이 유지되는지 확인한다. 390·768·1440px, 긴 한국어 제목, 영문, 실제 콘텐츠 이미지, 움직임 감소에서 검수한다. 폰트는 한글 지원과 대체 서체를 함께 정의하고, 사용자 폰트는 등록된 WOFF2 자산으로 관리한다. 서체가 없거나 늦게 로드되어도 편집할 수 있어야 한다.

## 5. 편집 자유도를 높이는 방안

### 선택과 내부 구조

- 선택 경로를 `페이지 > 구역 > 카드 > 제목`으로 보여주고, 겹친 요소 목록과 내부 편집 진입점을 제공한다. 기존 Ctrl/⌘+클릭과 키보드 조작도 유지한다.
- 조합 블록은 기존처럼 자식 요소를 직접 편집한다. 고정형 컴포넌트는 허용된 슬롯에 이미지·버튼·텍스트 등을 넣고 빼도록 확장한다.
- `독립 요소로 풀기`는 변환 가능한 컴포넌트부터 제공한다. 변환 후 레이아웃·문구·역할 매핑을 미리 보여주고, 사라질 동작을 표시하며 한 번 Undo로 복원한다. 탭·폼·달력 등을 무조건 일반 div로 해체하지 않는다.
- 반복 항목은 줄바꿈 문자열 대신 목록 UI에서 추가·삭제·복제·순서를 바꾼다. 각 항목의 ID를 보존해 순서 변경 뒤에도 그 항목의 텍스트·스타일·모션이 유지되게 한다.

### 배치·서식·반응형

- 패딩·갭을 캔버스 손잡이로 조절하고, 숫자 입력도 같은 명령을 사용한다. 그리드는 열 경계·행/열 간격·셀 병합 범위를 직접 선택한다.
- 크기 모드는 내용에 맞춤/부모 채움/고정에 더해 %, min/max, 비율과 유동형 글자 크기를 단계적으로 지원한다. 임의 CSS 문자열 대신 검증 가능한 값과 단위를 사용한다.
- 속성마다 현재 값의 출처를 `테마`, `컴포넌트`, `개별`, `태블릿`, `데스크톱`으로 표시한다. 한 속성만 상속으로 되돌릴 수 있게 한다.
- 기존 스타일 복사·붙여넣기는 서체만/색상만/표면만/모션만 선택하는 방식으로 보강한다. 기존 다중 선택의 혼합 값 표시는 유지한다.
- 첫 차수는 현재 모바일→태블릿→데스크톱 상속과 폭 미리보기를 유지한다. 사용자 정의 브레이크포인트는 마이그레이션 영향이 커 별도 후속 항목으로 둔다.
- 제목·본문 서체 분리, 여러 배경 레이어, 그라디언트 편집, 모서리별 반경, 상태별 색상을 추가한다. 라이브러리 팝업·포커스 같은 동작은 기존 접근성 구현과 연결한다.
- 배치와 모션의 이동값을 분리한다. 드래그할 때 모션 이동이 좌표에 섞이거나 재생 후 영구 위치가 바뀌지 않아야 한다.

### 재사용과 상태

- 기존 `내 블록`은 독립 사본으로 유지한다. 2차에 `공통 컴포넌트`를 더해 원본 수정과 인스턴스별 예외를 지원한다.
- 원본 변경의 영향과 개별 수정 충돌을 보여주고, 연결 해제로 일반 노드로 전환한다. 원본 삭제는 사용 중인 인스턴스를 깨뜨리지 않게 처리한다.
- `hover`, `focus`, `selected`, `open`, `loading` 중 해당 컴포넌트가 지원하는 상태를 골라 외형과 전환을 수정한다. 상태 미리보기는 실제 콘텐츠·구조를 바꾸지 않는다.
- 오른쪽 패널은 콘텐츠/배치/외형/동작으로 나누고, 선택에 필요한 설정을 우선 노출한다. 고급 타임라인은 사용할 때만 펼친다.

## 6. 미디어와 모션을 실제로 다루는 방식

### 자산 관리

자산 패널에 이미지·영상·오디오·폰트·벡터 모션을 등록하고 캔버스로 끌어 넣는다. 교체할 때 레이아웃, 크롭, 캡션, 연결, 모션은 가능한 한 보존한다. 파일명·크기·형식·길이·사용 위치·대체 설명·대표 이미지를 표시한다.

프로젝트 문서에는 자산 ID와 메타데이터를 저장하고 원본 Blob은 IndexedDB의 별도 저장소에 둔다. `blob:` URL은 실행 중에만 만들고 파일·공유·Undo 기록에 영구 주소로 쓰지 않는다. 바이너리를 JSON에 base64로 넣어 기존 3MB 문서 제한을 무력화하지 않는다.

1차 제한의 제안값은 이미지 10MB, 영상/오디오 각각 50MB, 프로젝트 전체 자산 150MB다. 실제 브라우저 할당량을 확인해 적용하며 제품 고정 보장으로 홍보하지 않는다. 저장 공간 부족 시 원본 작업을 유지하고 ZIP 백업을 제공한다. ZIP 가져오기는 해제 후 총 크기·파일 수·경로를 검증한다.

이미지와 폰트의 출처·이용 조건을 자산 메타데이터에 남긴다. 샘플 자산은 배포 가능한 자체 제작물 또는 조건을 확인한 자료를 사용한다. 공개 예제의 외부 이미지·영상을 무단으로 내려받아 템플릿에 포함하지 않는다.

### 동작 패널

쉬운 모드에서는 효과, 강도, 빠르기, 시작 조건을 고른다. 고급 모드에서는 대상, 시작/종료 값, 길이, 지연, easing, 반복, 재생 구간, 화면별 활성화, 정지 대체를 편집한다.

| 시작 조건 | 예 | 제어 |
| --- | --- | --- |
| 페이지 시작 | 제목 등장 | 지연·한 번 재생 |
| 화면 진입 | 카드 순차 등장 | 보이는 비율·한 번/재진입 |
| hover/focus/클릭 | 카드 반응·상태 전환 | 터치 대체·키보드 대응 |
| 스크롤 진행 | 이미지 이동·크기 변화·챕터 전환 | 기준 영역·시작/끝 위치 |
| 컴포넌트 상태 | 열림·선택·샘플 완료 | 기존 동작 상태와 연결 |

추가 효과 후보 12종은 단어 순차 등장, 숫자 변화, SVG 선 그리기, 이미지 마스크, 이미지 패럴랙스, 배경 크로스페이드, 카드 겹침 전환, 스크롤 확대, 포인터 조명, 자석형 호버, 상태 간 전환, 장면 간 전환이다. 이미 있는 fade/reveal/tilt와 구별할 동작이 없으면 기존 효과 옵션으로 합친다.

CSS로 충분한 효과는 CSS를 쓴다. 효과 하나를 적용할 때 거대한 런타임이 모두 로드되지 않도록 한다. 포인터 효과는 기본 포인터와 클릭 영역을 유지하고 터치 화면에서는 정지 표현을 쓴다. 스크롤을 강제로 가로채거나 브라우저의 기본 이동을 막는 방식을 기본값으로 두지 않는다.

### 편집·미리보기·캡처

| 상황 | 동작 계약 |
| --- | --- |
| 일반 편집 | 선택 영역이 안정되도록 모션 정지, 미디어는 포스터 표시 |
| 선택 장면 재생 | 선택한 장면만 재생하고 일시정지·처음으로 이동·구간 탐색 제공 |
| 전체 미리보기/공유 | 실제 트리거와 미디어 제어, 화면 밖/백그라운드 정지 |
| 모바일·움직임 감소 | 무거운 이동·3D를 정지 이미지/자연스러운 콘텐츠 흐름으로 대체 |
| PNG/썸네일 | 저장된 대표 상태/프레임으로 렌더링, 실패하면 명시한 포스터 사용 |
| AI 전달 | 정지 이미지에 더해 트리거·시간·자산·모바일 대체 명세 포함 |

일반 영상은 누르면 재생을 기본으로 한다. 배경 영상은 음소거·인라인 재생으로 시도하고, 차단되면 포스터와 재생 버튼을 제공한다. 자동 재생 성공을 가정하지 않는다. 오디오 자동 재생은 기본으로 제공하지 않는다. 근거: [MDN 미디어 자동 재생](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).

오래 반복되는 장식·배경에는 멈춤 기능을 제공한다. 움직임 감소만으로 재생 제어를 대체하지 않는다. 캡션·자막·대본과 키보드 조작도 컴포넌트의 속성으로 다룬다. 근거: [W3C Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html).

동영상/GIF/MP4 내보내기는 별도 기능으로 남긴다. PNG와 모션 명세를 제공한다고 영상 렌더링까지 지원하는 것으로 표시하지 않는다.

## 8. 문서 모델·저장·출력 설계

### 다음 스키마의 제안

문서 스키마 v5를 제안한다. IndexedDB 버전은 현재 2이며 자산 저장소 추가 시 별도 버전으로 관리한다. 문서 버전과 DB 버전을 혼동하지 않는다.

| 정보 | 설계 방향 |
| --- | --- |
| `assets` | 자산 ID, 종류, 로컬/원격 출처, MIME, 크기, 길이, 포스터/자막 참조, 이용 조건 |
| `theme` 확장 | 기존 색상 역할을 유지하며 타이포 역할, 추가 의미색, 표면·그라디언트, 팩 ID·버전 추가 |
| 구조화 콘텐츠 | 컴포넌트별로 검증하는 items/rows/columns 등; 임의의 모든 객체를 props에 허용하지 않음 |
| 슬롯·파트 | 노드 ID + 역할 ID + 반복 항목 ID. DOM 순번을 신규 편집 데이터의 기본 키로 쓰지 않음 |
| `motion` | 트리거, 대상, 시간, 허용 속성, 반복, 스크롤 구간, 화면별 설정, 대표 상태 |
| 컴포넌트 상태 | 지원 상태 목록과 상태별 외형 차이; 런타임 현재 상태와 저장된 초기값 구분 |
| 공통 컴포넌트 | 정의 ID·버전과 인스턴스 예외. 순환 참조·삭제·복제 규칙 포함 |

공통 컴포넌트처럼 후속 차수의 구조는 기능을 구현할 때 구체 스키마를 확정한다. 아직 지원하지 않는 기능을 빈 필드만 만들어 완료로 기록하지 않는다.

기본 외형 우선순위는 `테마 토큰 → 컴포넌트 기본값/외형 스타일 → 노드 공통값 → 현재 화면의 상속·수정값 → 현재 상태의 명시적 값`으로 명문화한다. 파트 수정은 대상 파트에 같은 규칙으로 적용한다. 편집 표시와 일시적인 미리보기 상태는 문서에 섞지 않는다.

테마 변경은 기존 개별 수정에 영향을 주지 않고, 사용자가 선택한 초기화 동작만 수정값을 제거한다. DTCG 토큰으로 표현 가능한 디자인 값과 미디어/모션 동작 명세를 분리해서 내보낸다.

### 호환성과 저장 수명

- v2/v3/v4 읽기 변환 경로와 첫 새 형식 저장 시 원본 체크포인트 보존을 유지한다.
- 기존 `appearance.motion`은 동일한 모양·시간·반복을 갖는 새 모션 설정으로 변환한다. 예전 모션 없음도 유지한다.
- 기존 문자열 목록은 각 항목의 ID를 한 번 생성하고 저장한다. 기존 `p.*` 수정이 있는 노드는 검증된 변환 매핑이 없으면 구형 어댑터로 보존한다.
- 바이너리는 Undo의 문서 스냅샷에 복제하지 않는다. 현재 문서, 수동 버전, 탭별 복구, Undo/Redo가 참조하는 자산을 유지한다.
- 저장 충돌·업그레이드 중 다른 탭·할당량 초과에서도 기존 프로젝트를 손상시키지 않는 저장 순서를 검증한다. 참조가 완전히 사라진 자산 정리는 별도 회수 절차로 처리한다.

### 렌더러와 좌표

미디어 런타임에 `load / play / pause / seek / snapshot / dispose` 계약을 둔다. 모든 엔진이 정확한 seek를 제공한다고 가정하지 않고 지원 능력과 대체 포스터를 함께 선언한다. Rive 상태 머신처럼 임의 시각 탐색이 어려운 경우 상태 입력값 또는 포스터를 대표 상태로 쓴다.

선택용 바깥 레이어가 배치 좌표·회전을 소유하고, 안쪽 레이어가 모션 변환을 소유한다. 스크롤 기준과 관찰자는 렌더러가 들어 있는 iframe의 문서/컨테이너에 연결한다. 미리보기의 iframe 스크롤, 편집기 스크롤, 페이지 내부 스크롤을 혼용하지 않는다.

### 백업·공유·AI 전달

| 출력 | 계획 |
| --- | --- |
| JSON | 설계와 자산 참조 저장. 로컬 자산 원본이 포함되지 않았음을 파일 내 명세와 UI에 표시 |
| 프로젝트 ZIP | 문서 + 자산 manifest + 원본/포스터/자막/폰트 + 버전 정보. 새 브라우저에서 다시 가져오기 지원 |
| URL 공유 | 현재처럼 설계 스냅샷. 공개 HTTPS 자산은 참조 가능; 로컬 자산은 다른 기기에서 열 수 없으므로 누락을 표시하고 ZIP 전달로 안내 |
| PNG | 실제 대표 상태 또는 포스터 사용. CORS/캔버스 캡처 실패를 숨기지 않고 자산별 대체 상태 기록 |
| AI ZIP | 기존 설계·테마·동작에 media manifest, motion specs, 대표 장면/화면별 대체 규칙 추가 |

로컬 파일을 공개 링크에서 그대로 볼 수 있게 하려면 별도 자산 호스팅이 필요하다. 계정·클라우드 저장 없이 그 기능까지 자동으로 해결된다고 약속하지 않는다. 현재 제품 방향에서는 자산을 포함한 ZIP 이동을 먼저 완성한다.

### 첫 구현 작업 단위

1. 기준 문서 6개 고정: 자동 배치, 자유 배치, legacy 파트 수정, 역할 파트 수정, 표/반복 목록, 큰 문서. 현재 저장·공유·PNG 결과를 비교 기준으로 보관한다.

3. 영상 플레이어와 이미지 교체 흐름을 세 브라우저에서 검증한다. 이때 미디어 불러오기 실패·자동 재생 차단·용량 부족도 다룬다.
4. 갤러리를 첫 구조화 목록 대상으로 전환하고, 항목 순서 변경 후 스타일과 자산 연결이 유지되는지 확인한다.

6. 나머지 첫 차수 팩과 신규 기능·장면을 추가한다. 기존 기능을 신규 항목으로 중복 집계하지 않는다.

## 11. 검증과 출시 판단

수량보다 아래 사용자 작업의 완결성을 우선한다. 수치는 목표이며 이번 조사에서 측정한 결과가 아니다.

- **편집 보존:** 테마/구조 변경, 반복 항목 순서 변경, 복사, 공통 컴포넌트 갱신 뒤에도 문구·자산·개별 수정이 유지된다. 한 번의 완료된 조작은 한 번 Undo로 복원한다.
- **이동 가능성:** 자산 포함 ZIP을 새 브라우저 프로필에 가져와 이미지·영상·폰트·모션 참조를 복원한다. JSON만으로 원본 파일이 이동했다고 표시하지 않는다.
- **반응형:** 모든 디자인 팩/장면을 390·768·1440px에서 검사하고, 320px 및 중간 폭은 대표 장면에서 추가 검사한다. 가로 장면은 모바일과 키보드 대체 경로를 가진다.
- **미디어 실패:** 코덱 미지원, 잘못된 MIME, 원격 CORS, 끊긴 URL, 없는 포스터, autoplay 차단에서 편집·백업 기능이 계속 동작한다.
- **모션 제어:** 키보드·터치·움직임 감소·백그라운드 정지를 확인한다. 모든 프레임에서 읽어야 할 내용과 조작 요소가 접근 가능하다.
- **렌더링 일치:** 편집의 정지 상태, 미리보기, 공유, PNG가 같은 토큰과 구조를 사용한다. 영상·Rive·WebGL의 캡처 대체는 결과물에 기록한다.
- **기능 회귀:** 기존 단위 테스트, 타입 검사, `lint:studio`, 정적 빌드를 수행한 뒤 변경 영향 범위의 Edge·Firefox·WebKit E2E를 실행한다. 실제 iOS/Android 검증은 엔진 자동 검사와 별도로 기록한다.
- **성능:** 기존 200노드/50행 입력 p95 100ms 미만 목표를 유지한다. 드래그와 미디어 성능은 별도 지표로 측정한다. 60Hz 기준 장면 프레임 간격 p95 20ms 이하를 초기 목표로 잡되, 하드웨어·브라우저·자산 크기·동시 재생 수를 함께 기록하고 낮은 사양 대체 모드를 검증한다.
- **로딩/메모리:** 빈 프로젝트에서 Rive/Lottie/3D 런타임과 자산을 요청하지 않는다. 화면 전환·재생 반복 뒤 영상·Canvas·Blob URL을 해제하고 지속 증가가 없는지 확인한다. 번들·메모리의 실제 예산은 0단계 측정치로 확정한다.
- **사용성:** 처음 쓰는 사람이 영상 교체, 테마 일부 적용, 카드 항목 추가, 모바일 수정, ZIP 복원을 도움 없이 수행하는지 관찰한다.
