## 목표와 현재 상태

목표는 **라이브러리에서 원하는 디자인을 끌어 놓고, 화면의 요소와 그 내부를 직접 움직이며 완성하는 편집기**다. 기능 종류, 디자인 변형, 조합 블록을 각각 확장한다.

현재 102개 삽입 항목(이 중 조합 블록 32개)과 자유 배치 이동·크기·회전·그룹·내부 부분 편집이 구현되어 있다. 다만 코드 확인 결과 다음 빈틈이 있다.

| 현재 동작 | 다음 변경 |
| --- | --- |
| 라이브러리 타일은 클릭으로만 추가 | 타일에서 캔버스로 끌어 정확한 위치에 삽입 |
| 자유 배치에서는 좌표 이동, 자동 배치에서는 구조·순서 변경 | 선택한 영역의 배치 방식을 화면에 명확히 표시하고 이동 결과를 미리 보여줌 |
| 자유 배치 드래그는 원래 부모 안에서 좌표 변경 | 다른 프레임으로 드롭하면 소속과 좌표를 함께 변환 |
| 컨테이너 배경 드래그가 영역 선택에 쓰임 | 컨테이너를 잡아 옮길 수 있는 이름표·이동 손잡이 제공 |
| 조합 블록 다수가 같은 기본 카드·스택 외형 사용 | 내용은 유지하면서 구조·타이포·표면을 바꾸는 디자인 프리셋 |
| 내부 수정은 주로 DOM 순서 경로에 연결 | 디자인을 바꿔도 유지되는 제목·설명·아이콘·동작 영역의 고정 식별자 도입 |

근거 파일은 `CanvasEditor.tsx`, `Editor.tsx`, `component-parts.tsx`, `more-catalog.ts`, `PreviewFrame.tsx`다. 자동 배치에도 일부 캔버스 이동 기능이 이미 있으므로 이를 새로 구현한 것으로 집계하지 않는다.

## 1. 끌어서 배치하는 흐름

1. **라이브러리 → 캔버스:** 끌고 있는 요소의 미리보기와 목적지 테두리, 삽입선을 보여준다. 자유 배치에서는 놓은 좌표에, 자동 배치에서는 표시된 순서·그리드 위치에 들어간다. 클릭 추가와 키보드 추가도 유지한다.
2. **캔버스 → 다른 영역:** 다른 프레임·카드로 옮길 때 들어갈 부모를 이름과 테두리로 표시한다. 잠긴 영역, 자기 자손, 허용되지 않는 내부 영역은 드롭 대상에서 제외한다. 자유→자동은 삽입 순서로, 자동→자유는 보이는 크기와 드롭 좌표로 변환한다.
3. **어디를 잡을지 명확하게:** 모든 컨테이너에 선택 시 이름표와 이동 손잡이를 제공한다. 빈 배경은 영역 선택, 이름표는 컨테이너 이동, 텍스트 더블클릭은 입력으로 일관되게 구분한다.
4. **자동/자유 전환:** 선택 영역 옆에 현재 배치 방식을 표시하고 ‘자유롭게 배치’로 바꾸면 현재 모양을 측정해 유지한다. 자동 배치의 드래그를 X/Y 이동처럼 안내하지 않는다. 처음부터 쓸 수 있는 ‘빈 자유 캔버스’ 프리셋도 추가한다.
5. **세밀한 조정:** 현재 실제 크기를 반영하는 X/Y/W/H, 방향키·Shift 이동, 중심·가장자리·동일 간격 안내, 가로/세로 이동 제한, Alt 스냅 해제, 가장자리 자동 스크롤을 제공한다. 수정하지 않고 숫자 필드를 나가면 크기 방식을 바꾸지 않는다.
6. **컴포넌트 내부:** 제목·버튼·아이콘·이미지의 이름 있는 선택 영역, 선택 경로, 내부 이동·리사이즈 손잡이를 제공한다. Ctrl/⌘+클릭 외에도 ‘내부 편집’ 버튼으로 진입할 수 있다. 항목 순서 변경과 스타일 이동을 구분한다.

같은 부모의 다중 이동을 우선 완성하고 다른 부모의 다중 이동은 부모 변경 규칙을 검증한 후 확장한다. 겹친 요소 목록, 우클릭 메뉴, 복제·정렬·잠금·앞뒤 순서는 선택 도구와 연결한다. 어떤 조작도 한 번 놓으면 실행 취소 한 번으로 복원되어야 한다.

## 2. 기능과 디자인을 함께 확장

확장 규모는 아래의 **목표 수량**으로 관리한다. 실제 구현 수량과 구분하며, 색상만 바꾼 항목을 새로운 기능 컴포넌트로 세지 않는다.

| 항목 | 목표 | 의미 |
| --- | --- | --- |
| 기능 유형 | 기존 102개 + 신규 30개를 목표로 선정 | 서로 다른 입력·탐색·데이터·배치 기능 |
| 자주 쓰는 요소의 디자인 | 24종 × 최소 6개 = 144개 프리셋 | 같은 내용을 유지하면서 외형을 바꾸는 선택지 |
| 조합 블록 디자인 | 12개 분류 × 6개 = 72개 구조 프리셋 | 실제 배치가 다른 화면 구역; 기존 블록과 겹치는 것은 교체·보강으로 집계 |
| 모션·장식 | 우선 12개 효과 프리셋 | 기능 유형 수에 중복 합산하지 않는 선택 효과 |

신규 30개 후보는 다음과 같다. shadcn/ui에 있는 요소와 자체 확장 후보가 섞여 있으며 모두 shadcn 공식 컴포넌트라고 표시하지 않는다.

| 분류 | 후보 |
| --- | --- |
| 입력 8개 | 검색형 선택, 다중 선택, OTP 입력, 접두·접미 입력 묶음, 날짜 범위 선택, 비밀번호 입력, 색상 견본, 다중 토글 묶음 |
| 탐색·오버레이 9개 | 명령 검색창, 우클릭 메뉴, 메뉴바, 메가 메뉴, 팝오버, 호버 카드, 사이드 시트, 드로어, 확인 대화상자 |
| 콘텐츠·데이터 9개 | 캐러셀, 트리, 파일 목록 탐색기, 코드 블록, 터미널 표시, 선 차트, 영역 차트, 레이더 차트, 히트맵 |
| 배치·보조 4개 | 크기 조절 분할 패널, 스크롤 영역, 토글 버튼, 복사 버튼 |

버튼·입력창·카드·탭·표·사이드바 등 기존 기능은 추가 개수에 넣지 않고 품질과 디자인을 개선한다. 데이터 표에는 검색·정렬·행 선택·페이지 이동·열 표시를 보강한다. 파일 탐색기와 터미널은 샘플 데이터 표시이며 로컬 파일 시스템이나 명령 실행 기능을 뜻하지 않는다.

## 3. 참고 라이브러리와 도입 방식

2026-10-06에 공식 문서에서 확인한 후보를 사용한다. 아래의 역할 구분은 이번 제품에 맞춘 제안이며 인기 순위 주장은 아니다.

| 기반 | 적용 방향 |
| --- | --- |
| [shadcn/ui Components](https://ui.shadcn.com/docs/components), [Blocks](https://ui.shadcn.com/blocks) | 버튼·폼·탐색·대화상자·데이터 UI의 실제 동작 기반. 공식 소스를 프로젝트에 포함하고 편집기용 어댑터 연결 |
| [Magic UI](https://magicui.design/docs/components/bento-grid) | 벤토 그리드, 로고·리뷰 흐름, 숫자 변화, 테두리 강조 등 랜딩 디자인·효과 후보 |
| [Aceternity UI](https://ui.aceternity.com/components) | 히어로·카드·배경·호버 표현 후보. 조작하기 쉬운 효과부터 선별 |
| [React Bits](https://www.reactbits.dev/get-started/index) | 타이포그래피·진입·배경 모션의 추가 후보. 가벼운 효과부터 적용 |

shadcn/ui는 비슷한 외형만 만드는 것으로 끝내지 않고 공식 구현을 연결한다. 먼저 Button·Input·Card·Tabs·Dialog·Select·Combobox·Command·Sheet·Sidebar·Table·Date Picker의 대표 12개를 통합 대상으로 삼는다. Radix 기반 구현을 우선 검증해 프리미티브 계열을 통일한다. 기존 요소의 기본 모습은 보존하고 새 디자인을 선택한 경우에 전환한다.

외부 소스는 출처·버전·적용 조건을 함께 기록한다. 무료로 사용할 수 있는 공개 항목을 우선하며 유료 항목은 임의로 가져오지 않는다. 외부 레지스트리는 [shadcn Registry](https://ui.shadcn.com/docs/registry)의 구조를 참고해 개발 단계에서 검토·등록한다. 제품 사용 중 임의 코드를 바로 실행하는 가져오기는 이번 범위에 포함하지 않는다.

## 4. 디자인 다양성의 기준

스타일군은 **미니멀, 부드러운 SaaS, 테두리 중심, 뉴브루탈리즘, 에디토리얼, 글래스, 다크 테크, 컬러풀**의 8개 방향으로 둔다. 기능별로 적합한 스타일을 최소 6개 제공하며 모든 요소에 억지로 같은 8개를 적용하지 않는다.

- 버튼: 채움·윤곽·소프트·텍스트·그라디언트·굵은 그림자. 크기·아이콘 위치·로딩 상태는 별도로 조정한다.
- 카드: 기본·이미지 중심·가로형·벤토형·유리 표면·테두리 강조. 제목·이미지·동작 영역을 개별 편집한다.
- 히어로: 중앙형·좌우 분할·이미지 배경·앱 화면 강조·타이포 중심·벤토형.
- 가격표: 가로 비교·세로 목록·강조 플랜·단일 플랜·월/연 전환·표 비교.
- 인증·설정: 작은 폼·이미지 분할·단계형·탭형·사이드바형·넓은 대시보드형.

조합 블록 12분류는 히어로, 헤더/탐색, 기능 소개, 가격, 후기, FAQ, CTA, 인증, 대시보드, 설정/프로필, 커머스, 콘텐츠/푸터다. 색뿐 아니라 배치, 서체 크기와 대비, 여백, 테두리, 그림자, 이미지 비율이 실제로 달라야 한다.

스타일을 바꾸어도 문구·이미지·입력값 정의·위치·크기를 유지한다. 구조 프리셋 변경은 제목·본문·미디어·동작 같은 공통 역할로 내용을 옮기고 전후 결과를 미리 보여준다. 매핑할 수 없는 내부 수정은 조용히 버리지 않고 유지 가능한 원래 디자인과 변경 결과를 비교할 수 있게 한다.

## 5. 라이브러리 사용 경험

- 기본 요소 / UI 컴포넌트 / 화면 블록 / 효과 탭과 용도·디자인·출처 필터를 제공한다.
- ‘버튼’, ‘히어로’를 선택하면 디자인 변형이 실제 썸네일로 펼쳐진다. 같은 아이콘과 색만 바꾼 공통 그림으로 대체하지 않는다.
- 선택한 디자인을 그대로 끌어 넣을 수 있다. 큰 미리보기에서는 모바일·데스크톱과 기본·활성·오류·로딩·열림 상태를 확인한다.
- 즐겨찾기·최근 사용을 제공하고, 본인이 수정한 블록을 ‘내 블록’으로 저장해 독립된 사본으로 재사용한다. 연결된 공통 인스턴스는 후속 범위다.
- 선택한 요소의 속성 패널에서도 같은 기능의 다른 디자인으로 바꿀 수 있다.

## 6. 구현 기반과 호환성

| 영역 | 구현 방향 |
| --- | --- |
| 조작 세션 | 라이브러리 추가, 캔버스 이동, 부모 변경을 공통 명령으로 처리. 조작 중 임시 화면만 갱신하고 놓을 때 한 번 기록 |
| 좌표·드롭 | 바깥 문서와 iframe 사이의 포인터 좌표, 확대율, 스크롤, 회전을 한 경로로 변환. 프레임 밖 이동·Esc·취소 시 복원 |
| 정의 구조 | 기능 정의, 시각 프리셋, 조합 블록 레시피, 효과 정의를 분리. 모든 변형을 거대한 별도 렌더러 분기로 늘리지 않음 |
| 내부 편집 | DOM 순서 대신 title, description, media, action 등 역할 식별자와 반복 항목 ID를 사용. 기존 부분 수정은 변환 가능한 것부터 옮기고 나머지는 기존 렌더링으로 보존 |
| 스타일 | 프로젝트 테마 → 요소 디자인 → 사용자 수정 순서. 편집기와 미리보기의 스타일을 분리하고 필요한 CSS를 iframe·PNG·공유에서 함께 로드 |
| 오버레이 | Dialog·Popover·Sheet의 포털을 현재 미리보기 iframe 안에 생성. 포커스 복원·위치 계산·레이어 선택을 같은 문서 기준으로 처리 |
| 문서 형식 | 안정된 내부 식별자·디자인 정보를 담는 v4를 제안. v2/v3 읽기와 변환 전 원본 백업을 유지하고 알 수 없는 값 때문에 기존 내용을 버리지 않음 |
| 모션 | 편집 중에는 선택이 안정되도록 정지, 미리보기에서 재생. 화면 밖 효과는 멈추고 모션 감소 설정을 따름. PNG는 정해진 정지 상태로 출력 |
| 성능 | 효과와 큰 라이브러리 예시는 필요할 때 로드. 썸네일은 정적 캡처 중심으로 유지하고 모든 애니메이션을 목록에서 동시에 실행하지 않음 |

설치된 Next.js 안내를 읽은 뒤 의존성과 클라이언트 경계를 변경한다. 공유·내보내기에는 디자인 식별자와 버전, 내부 역할, 반응형 배치, 모션의 정지 표현까지 포함한다. 기존 공유 링크를 새 렌더러로 열 때 기본 모습이 바뀌지 않도록 이전 기본 디자인을 유지한다.

## 7. 구현 순서와 완료 기준

| 차수 | 결과물 | 완료 기준 |

## 8. 검증 시나리오

1. 50%·100%·200% 확대, 중첩·회전·스크롤 프레임에서 드롭 위치와 저장 좌표가 일치한다. 빈 영역, 자동 영역, 자유 영역 사이 이동도 검증한다.
2. 컨테이너 이동과 영역 선택이 구분되고 잠금·겹침·숨김·부모 자손 관계가 유지된다. Esc·포인터 취소·페이지 전환 시 미완성 조작을 저장하지 않는다.
3. 모바일·태블릿·데스크톱의 배치 상속, 다른 화면의 설정 보존, 키보드 조작과 실제 한국어 입력을 확인한다.
4. 디자인 변경 후 내용과 명시적으로 유지하기로 한 내부 수정이 보존된다. 표 정렬·항목 추가·삭제·재배열 이후에도 같은 항목을 편집한다.
5. 팝업·드로어의 열림 상태, 키보드 이동, 포커스 복원, 모션 감소, 라이트·다크 대비를 검사한다. 자동 검사 외에 실제 조작도 확인한다.
6. 200요소 문서의 입력 p95 100ms 미만을 유지하고 드래그 반영 p95 50ms 이하를 목표로 별도 측정한다. 엔진·DPR·측정 조건을 기록하며 목표와 측정 결과를 구분한다.
7. v2/v3 가져오기·저장·복구·충돌·공유 회귀 검사, 대표 디자인의 PNG 비교, 타입·린트·빌드를 확인한다. 추가 검증 없이 모든 과거 테스트 수를 새 변경의 통과 수로 재사용하지 않는다.

구현과 검증 후 배포는 기존 `prompt-studio-design` Sites 프로젝트와 주소를 계속 사용한다.

## 사용자가 경험할 편집 방식

### 직접 조작

- 클릭하면 선택 테두리와 크기 조절 핸들이 보인다. 드래그로 이동하고 모서리·변 핸들로 크기를 조절한다.
- 오른쪽 패널에서 X/Y/W/H를 직접 입력할 수도 있다. 자동 배치에서는 적용 가능한 크기·순서·간격을 보여준다.
- 자유 배치에서 방향키는 1px, Shift와 방향키는 10px 이동한다. 입력 필드나 한글 조합 중에는 편집 단축키가 개입하지 않는다.
- Esc로 진행 중인 조작을 취소한다. Ctrl/Cmd+Z로 완료한 조작을 되돌린다.
- 선택한 요소가 화면 밖에 있으면 레이어에서 선택한 뒤 화면 안으로 가져올 수 있다.

### 여러 요소를 한꺼번에 편집

- Shift+클릭과 빈 공간에서 드래그하는 선택 상자로 여러 요소를 고른다.
- 왼쪽·가운데·오른쪽, 위·중간·아래 정렬과 동일 간격 배치를 제공한다.
- 그룹·해제, 복제, 복사·붙여넣기, 앞으로·뒤로 보내기, 잠금·숨김을 제공한다.
- 다중 선택 속성은 공통값만 표시하고 다른 값은 ‘혼합’으로 표시한다. 변경한 항목만 선택 요소에 함께 적용한다.
- 첫 버전의 그룹과 일괄 정렬은 같은 부모 안의 요소를 대상으로 한다. 서로 다른 부모를 다루는 기능은 좌표 변환 검증 후 확장한다.

### 콘텐츠와 외형 편집

- 텍스트를 더블클릭하면 캔버스에서 바로 수정한다. 글자 크기·굵기·색상·정렬·행간을 조절한다.
- 요소별 배경·테두리·모서리·불투명도·그림자를 조절하고 프로젝트 테마로 되돌릴 수 있다.
- 이미지의 비율 유지, 채우기·맞춤, 초점 위치와 자르기를 제공한다.
- 사각형·원·선·텍스트 상자를 추가해 배지, 장식, 강조 영역을 직접 만든다.
- 회전과 다중 요소 크기 조절은 기본 이동·리사이즈가 안정화된 다음 추가한다. 요소 크기 변경과 글자까지 함께 확대하는 동작은 구분한다.

### 작업 화면

상단에는 선택·화면 이동 도구, 실행 취소, 화면 폭, 확대, 미리보기를 둔다. 왼쪽은 페이지·레이어·요소 추가, 가운데는 캔버스, 오른쪽은 선택 대상의 배치·외형·콘텐츠 속성으로 구성한다. 선택 근처에는 정렬·복제·앞뒤 순서처럼 자주 쓰는 동작만 표시한다.

Space+드래그로 작업 화면을 이동하고 확대·축소, 전체 맞춤, 선택 요소 맞춤을 제공한다. 편집 중의 클릭은 요소 선택에 사용하고, 미리보기에서는 버튼·폼·탭의 실제 동작을 확인한다. 편집 표시와 안내선은 캡처·공유 화면에 포함하지 않는다.

## 자동 배치와 자유 배치의 규칙

| 구분 | 자동 배치 | 자유 배치 |
| --- | --- | --- |
| 이동 | 형제 순서와 부모 영역 변경 | 부모 영역 안에서 X/Y 변경 |
| 크기 | 내용 맞춤·남은 공간 채우기·고정 크기 | 고정 크기·내용 높이·비율 유지 |
| 정렬 | Flex/Grid 정렬과 gap | 가장자리·중심·동일 간격에 맞춤 |
| 겹침 | 기본적으로 문서 흐름을 따름 | 앞뒤 순서를 지정해 겹침 허용 |
| 화면 폭 변경 | 기존 반응형 레이아웃 상속 | 화면별 좌표·크기와 후속 앵커 규칙 |

‘자동/자유’는 부모가 자식을 배치하는 방식이다. 부모 자신은 바깥 영역의 자동 배치 안에 있으면서 내부만 자유 배치일 수 있다. 전체 페이지를 고정 화면처럼 만드는 경우에는 루트 영역에 명시적인 크기를 지정한다.

자동 배치에서 자유 배치로 바꾸면 현재 보이는 자식들의 위치와 크기를 측정해 보존한다. 자유 배치에서 자동 배치로 바꾸면 레이어 순서대로 재배치될 결과를 미리 보여주고 사용자가 적용한다. 변환 전체는 실행 취소 한 번으로 복원한다.

자유 배치 영역은 높이를 명시적으로 가진다. 자식이 문서 흐름에서 빠져도 다음 섹션과 겹치거나 부모 높이가 0이 되지 않게 한다. ‘내용에 맞춰 영역 크기 조절’은 별도 명령으로 제공한다. 부모 밖으로 나간 요소는 기본적으로 보이게 하고 ‘영역 밖 자르기’를 선택할 수 있게 한다.

첫 버전에서 자유 배치 좌표와 크기는 부모 내부의 CSS px로 저장한다. 확대 배율이나 테마 밀도를 좌표에 곱해 저장하지 않는다. 자유 배치 자식에 자동 배치용 margin·span·fill 규칙을 중복 적용하지 않는다.

## 반응형 편집

기존 mobile 기본값 → tablet → desktop 상속을 유지한다. 패널에 현재 수정 범위와 상속 여부를 표시하고 ‘이 화면의 수정값 초기화’를 제공한다.

기존 영역을 자유 배치로 전환할 때 다른 화면 크기의 유효한 배치는 보존한다. 예를 들어 데스크톱에서 만든 이미지와 배지의 겹침이 모바일의 세로 배치를 자동으로 덮어쓰지 않도록 전환 시 필요한 화면별 값을 명시적으로 만든다.

첫 버전은 화면별 배치와 크기 조정을 제공한다. 좁은 화면에서 발생한 잘림·겹침을 확인할 수 있게 하고, 자동으로 적절한 모바일 배치를 만들어 준다고 약속하지 않는다. 다음 단계에서 왼쪽·오른쪽·중앙 고정, 양쪽 늘리기, 비례 위치 등 크기 변화에 대응하는 규칙을 추가한다.

| 외형 | 개별 스타일과 테마 참조, 불투명도, 후속 회전 |
| 화면별 변경값 | 배치·크기·외형의 상속과 재정의 |
| 자식 배열 | 레이어 순서와 자유 배치의 기본 겹침 순서 |

선택 목록·호버·안내선·진행 중인 드래그·확대·이동 상태는 프로젝트 데이터와 분리한다. 앞뒤 순서는 첫 버전에서 같은 부모의 자식 배열로 관리해 별도의 z-index와 순서가 불일치하지 않게 한다. 그룹은 자식을 가진 실제 컨테이너로 표현한다.

v2 문서는 읽을 수 있게 유지하고, 메모리에서 변환·검증한 후 저장한다. 원본 복구 자료를 확보한 뒤 새 버전을 기록하며 저장 실패 시 원본을 유지한다. IndexedDB, JSON 가져오기, 공유 링크, 체크포인트, 미저장 복구본, 템플릿에 같은 변환 규칙을 적용한다. 이전 앱이 v3 문서를 읽을 수 있다고 가정하지 않는다.

### 캔버스와 입력

기존 DOM 렌더러와 iframe 격리를 유지하는 방향으로 먼저 검증한다. 선택 테두리·핸들·안내선은 iframe 내부의 독립된 편집 오버레이로 그려 실제 콘텐츠의 레이아웃을 바꾸지 않게 한다. 미리보기와 캡처에서는 오버레이를 렌더링하지 않는다.

좌표 계산은 화면 좌표, 확대된 iframe, iframe 스크롤, 부모 내부 좌표를 명시적으로 구분하는 공통 모듈로 모은다. 중첩 부모와 여백을 반영하고, 부모를 옮기는 경우에는 새 부모 기준 좌표로 변환한다. 회전을 추가할 때는 역변환을 포함한 행렬 계산으로 확장한다.

포인터 조작은 선택 → 이동 준비 → 드래그/리사이즈 → 확정/취소 단계로 관리한다. 클릭과 드래그의 판별 거리, 포인터 캡처, iframe 밖 이동, 포커스 상실, pointercancel, 화면 전환 때의 취소를 정의한다. 스냅의 판정 거리는 화면상 픽셀 기준으로 유지해 확대율에 따라 조작감이 크게 달라지지 않게 한다.

### 기록과 성능

현재 `editProject`는 문서를 복제하고 전체 검증하며, `useEditor`는 시간 간격으로 기록을 묶는다. 매 포인터 이동마다 이 경로를 호출하지 않는다.

드래그 중에는 임시 상태로 화면과 숫자만 갱신하고, 포인터를 놓을 때 한 번 검증·커밋·저장한다. 취소하거나 원래 위치로 돌아오면 기록을 만들지 않는다. 오래 끌어도 한 번의 조작은 하나의 기록으로 남는다. 키보드 연속 이동도 키를 누른 구간을 묶어 처리한다.

문서 변경 명령과 포인터 처리, 선택 상태, 좌표 계산을 분리해 `Editor.tsx`에 모두 누적시키지 않는다. 히트 테스트와 스냅 후보는 현재 페이지·영역에 한정하고 조작 중 DOM 측정과 갱신 횟수를 제한한다.

### 컴포넌트 내부 편집

일부 히어로·기능 카드 등은 제목·설명·버튼을 하나의 렌더링 컴포넌트 안에 가지고 있다. 바깥 박스의 위치만 자유롭게 만들어도 내부 요소는 따로 움직일 수 없다.

제목·본문·버튼·이미지 같은 기본 요소부터 직접 편집을 완성한다. 이후 자주 쓰는 복합 블록을 자식 노드로 구성하는 편집 가능한 패턴으로 바꾼다. 기존 블록은 지원되는 경우 ‘내부 요소 편집’으로 변환하고 원래 모양과 내용을 보존한다. 폼·탭·표처럼 의미와 동작이 연결된 요소는 무조건 분해하지 않고 항목·영역별 편집을 제공한다.

### 렌더링과 AI 전달

크기·외형 해석은 편집, 미리보기, PNG, 공유에서 같은 로직을 사용한다. 현재 기본 CSS의 최대 너비, 내부 고정 여백, 글자 크기, 높이 규칙이 새 크기·스타일 설정을 덮어쓰는 경우를 함께 정리한다.

전달 JSON과 프롬프트에는 자동/자유 배치, 부모 좌표 기준, 화면별 크기, 겹침 순서, 텍스트와 이미지 규칙을 포함한다. 자유 배치를 CSS의 상대 부모와 절대 자식으로 재현할 수 있게 설명하고 기존 Flex/Grid 의미도 유지한다. 전달 형식과 렌더러 버전도 갱신한다. 내보내기 지원은 각 기능이 추가되는 단계에 함께 완료한다.

## 단계별 구현과 완료 기준

| 단계 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 0 기반 검증 | 대표 자유 배치 영역, 좌표 변환 실험, 명령·임시 상태 분리, v3 변환 설계 | 중첩·스크롤·확대 상태에서 측정과 이동이 일치하고 v2 원본 보존 경로가 정해짐 |
| 1 직접 편집 MVP | 단일 선택 오버레이, 이동·8방향 크기 조절, X/Y/W/H, 자유 배치 영역, 기존 자동 배치의 캔버스 순서 이동, 기본 가장자리·중심 스냅, 키보드 이동 | 실제 화면을 직접 조작하고 저장·복원·Undo·공유·PNG·AI 전달에서도 결과가 유지됨 |
| 2 배치 생산성 | 다중 선택·범위 선택, 일괄 이동, 정렬·동일 간격, 그룹·해제, 복사·붙여넣기, 앞뒤 순서, 화면 이동·선택 맞춤 | 같은 부모의 카드 3개를 선택해 간격을 맞추고 그룹으로 이동한 뒤 한 번에 되돌릴 수 있음 |
| 3 편집 다양성 | 인라인 텍스트, 개별 스타일, 이미지 자르기, 기본 도형, 회전, 복합 블록 내부 편집 | 히어로의 제목·버튼·이미지를 각각 편집하고 한국어 입력·실제 컴포넌트 동작이 유지됨 |
| 4 반응형과 확장 | 앵커·늘리기 규칙, 레이아웃 변환 미리보기 고도화, 다중 크기 조절, 스타일 복사, 재사용 패턴 | 데스크톱 자유 배치와 모바일 자동 배치를 같은 프로젝트에서 안정적으로 수정·전달할 수 있음 |

1단계의 기본 스냅은 부모와 형제의 가장자리·중심을 대상으로 한다. 같은 간격 자동 안내는 2단계에 추가한다. 1단계에서도 고정 화면만 확인하지 않고 기존 자동 배치와 화면별 설정의 동작을 함께 검증한다.

첫 구현 묶음은 **자유 배치 영역 하나에 제목·버튼·이미지를 놓고 직접 이동·리사이즈하는 흐름**으로 제한한다. 라이브러리의 캔버스 드롭 삽입과 편집 가능한 패턴은 후속으로 연결한다. 사용성 검증 뒤 회전·고급 도형·재사용 인스턴스의 우선순위를 조정한다.

## 검증 시나리오

1. 50%·100%·200% 확대, 바깥 캔버스와 iframe 내부 스크롤, 중첩 영역에서 같은 문서 좌표 이동량이 보존된다. 조작으로 breakpoint가 달라지지 않는다.
2. 2초 이상 드래그해도 실행 취소 한 번으로 복원된다. Esc·포인터 취소·페이지 전환은 불완전한 문서를 저장하지 않는다.
3. 최소 크기, 부모 경계, 내용이 긴 텍스트, 비율 잠금, 숨김·잠금·잠긴 부모, 겹친 요소 선택을 확인한다. 자동 배치에서 임의 X/Y가 적용되지 않는다.
4. 그룹·해제와 부모 이동 전후에 화면상 위치가 의도대로 유지된다. 부모와 자식의 중복 선택 때문에 두 번 이동하지 않는다.
5. 자유 배치 섹션 아래의 본문이 정상 위치에 있고 모바일 배치가 보존된다. 프리셋의 기존 Flex/Grid 화면도 비교한다.
6. v2 파일·저장 프로젝트·공유·체크포인트·복구본을 읽고, v3 저장 후 새로 열어 배치와 스타일을 확인한다. 기존 저장 실패·충돌 복구 검사도 통과한다.
7. 캔버스, 미리보기, PNG, 공유, 전달 JSON의 위치·크기·겹침이 일치한다. 편집 핸들이 출력에 들어가지 않는다.
8. 한국어 조합 입력, 입력창 안의 방향키·복사·Undo, 키보드만으로 하는 선택·숫자 편집, 포커스 표시를 검증한다.
9. 기존 200요소 입력 성능 측정에 드래그 시나리오를 추가한다. 같은 환경에서 조작 반영 p95 50ms 이하를 초기 목표로 두고 측정 방법·엔진·DPR·프레임 지연을 함께 기록한다. 현재 남아 있는 WebKit 성능 문제는 별도 해결 대상으로 유지한다.

문서 모델과 좌표 변환은 단위 테스트, 실제 드래그·리사이즈·저장·내보내기는 Playwright로 검증한다. 각 단계에서 변경 범위의 검사와 `typecheck`, `lint:studio`, 프로덕션 빌드를 통과시킨다. 핵심 상호작용은 Edge·Firefox·WebKit에서 확인하고 실제 한국어 IME는 수동 검사도 수행한다.

## 이번 확장의 범위

이번 계획의 우선 결과물은 Prompt Studio 안에서 쓰는 직접 편집 경험이다. `.fig` 또는 `.pptx` 가져오기·내보내기, 실시간 협업, 벡터 펜·경로 편집, 슬라이드 발표 기능은 별도 요구가 생길 때 계획한다.

제품 목적과 로그인 없는 저장 방식은 [제품 계획](PRODUCT_PLAN.md)을 따른다. 프레임워크 코드를 수정할 때는 저장소 지침대로 설치된 Next.js의 `node_modules/next/dist/docs/`를 확인한다. 편집 기능은 현재 클라이언트 영역과 정적 배포 구조 안에서 확장한다.
