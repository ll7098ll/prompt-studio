# 데이터 저장과 개인정보

이 문서는 현재 코드가 데이터를 다루는 방식을 설명합니다. 별도 사업자의 법률 문서나 약관을 대신하지 않습니다.

## 어디에 저장하나요?

| 자료                  | 위치 / 성격                             |
| --------------------- | --------------------------------------- |
| 프로젝트와 수동 버전  | 현재 사이트·브라우저 프로필의 IndexedDB |
| 탭별 미저장 복구 자료 | localStorage 기반 로컬 복구 자료        |
| 실행 취소             | 현재 편집 세션의 메모리 상태            |
| JSON·PNG·ZIP          | 사용자가 선택해 다운로드한 파일         |
| 공유 설계             | 공유 URL의 fragment에 압축한 스냅샷     |

계정·로그인·서버 프로젝트 DB·기기 간 자동 동기화가 없습니다. 브라우저 데이터 삭제, 저장 공간 제한, 개인 모드 종료나 기기 변경으로 작업을 잃을 수 있으므로 JSON을 별도로 보관하세요.

## 공유 범위

공유 링크에 설계 내용이 포함됩니다. 링크를 가진 사람은 내용을 보고 사본을 만들 수 있습니다. 압축은 암호화가 아니며 회수·만료·비밀번호 보호는 없습니다.

브라우저는 URL fragment를 일반 HTTP 요청 경로에 포함하지 않지만, 링크 전체는 클립보드·브라우저 기록·전달한 메신저 등에 남을 수 있습니다. 비공개 콘텐츠가 포함된 설계는 공유 전에 검토하세요.

## 외부 요청

현재 편집기에는 개인 설계를 원격 분석·오류 수집 서비스에 자동 전송하는 코드가 없습니다. 다만 다음 요청은 구분해야 합니다.

- 사이트를 열면 호스팅에 정적 파일을 요청합니다.
- 사용자가 입력한 외부 이미지 URL을 불러올 수 있습니다.
- 앱 빌드 시 Geist 계열 폰트를 Google Fonts에서 가져옵니다.
- 보존된 `/legacy/` 화면에는 Google Fonts·jsDelivr 폰트와 Unsplash 이미지 요청이 있습니다.
- 외부 AI에 파일을 첨부하는 행위는 사용자가 선택한 AI 서비스로 자료를 전달하는 것입니다.

따라서 전체 앱을 완전한 오프라인·무통신 서비스로 설명하지 않습니다.

## 삭제와 복구

프로젝트 삭제 기능과 브라우저의 사이트 데이터 삭제는 범위가 다릅니다. 완전한 로컬 정리를 원하면 먼저 필요한 JSON을 백업하고 해당 사이트의 브라우저 데이터를 삭제합니다. 이미 다운로드한 파일이나 다른 사람에게 전달한 링크·사본은 함께 지워지지 않습니다.

저장 오류나 손상 진단 자료를 제보할 때는 실제 문구·이미지 URL·프로젝트 원문을 제거하고 최소 재현 예제로 바꾸세요. `studio-storage-recovery.json`에는 원시 복구 자료가 들어갈 수 있으므로 공개 이슈에 그대로 올리지 마세요.
