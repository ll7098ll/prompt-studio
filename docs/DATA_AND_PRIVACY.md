# 데이터·백업·공유

## 저장 위치

프로젝트는 브라우저 IndexedDB에 문서·체크포인트·자산을 보관합니다. localStorage에는 탭별 미저장 복구본을 기록합니다. 계정 동기화와 원격 프로젝트 데이터베이스는 없습니다.

같은 도메인이라도 프로토콜·포트·브라우저 프로필이 다르면 저장 공간이 달라집니다. 브라우저 데이터 삭제, 저장 공간 부족, 비공개 창의 수명에 따라 로컬 기록이 사라지거나 저장에 실패할 수 있습니다. 중요한 작업은 자산 포함 ZIP으로 백업합니다.

## 백업 종류

| 자료             | 포함 범위                       | 주의점                                    |
| ---------------- | ------------------------------- | ----------------------------------------- |
| 프로젝트 JSON    | v5 설계와 자산 메타데이터       | 로컬 파일 원본 없음                       |
| 자산 포함 ZIP    | `project.json`과 자산 원본·목록 | 기기 이동과 전체 복원용                   |
| AI 전달 ZIP      | 설계·토큰·명세·자산·선택 캡처   | 구현 자료와 백업을 함께 포함              |
| 공유 링크        | 압축된 설계 스냅샷              | 로컬 파일 원본 없음, 링크 회수 없음       |
| 저장소 진단 백업 | 문서·체크포인트·원시 복구 자료  | 모든 자산의 완전한 백업으로 사용하지 않음 |

공유 링크를 받은 사람은 설계 데이터를 읽고 사본을 만들 수 있습니다. 원본 수정은 이미 발행한 링크를 바꾸지 않습니다. 비공개 설계·연락처·비밀값을 링크에 넣지 마세요. URL fragment는 서버 요청 경로에 포함되지 않지만 링크 자체에 설계가 들어 있습니다.

소스 경로는 `src/builder/` 기준입니다. MB는 위 바이트 수 기준이며 브라우저가 실제로 보장하는 저장 용량은 별개입니다.

## 외부 요청과 검증

개인 설계 분석·원격 오류 수집을 전송하는 코드는 없습니다. 사용자가 지정한 외부 이미지·미디어와 외부 링크, 정적 호스팅의 접속 기록은 별도입니다. 앱 빌드에는 Google 서체 다운로드가 필요할 수 있습니다.

가져오는 문서는 Zod·트리 검증을 통과해야 하며 등록된 컴포넌트와 속성만 사용합니다. 임의 JavaScript를 프로젝트에 넣어 실행하는 기능은 없습니다. 자산은 파일 시그니처·종류·크기·해시를 확인합니다. 캡처용 외부 이미지는 해당 서버의 CORS 허용이 필요합니다.

## 복구

자동 저장 실패 시 현재 작업을 JSON으로 다운로드하거나 사본 저장을 사용합니다. 두 탭의 충돌은 원본을 덮어쓰지 않습니다. **복구 자료**에서 탭별 미저장 작업을 찾아 복원합니다.

`studio-storage-recovery.json`은 손상 기록과 원시 문자열을 포함하는 진단 자료입니다. 유효한 `project` 객체를 별도 JSON으로 꺼내 일반 파일 열기로 복원할 수 있습니다. 문제 제보에는 실제 개인 프로젝트 대신 재현용 자료를 사용하세요.
