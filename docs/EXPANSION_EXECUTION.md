# 디자인·미디어 확장 실행 기록

기준: 2026-10-07. [승인된 계획](DESIGN_MEDIA_EDITOR_EXPANSION_PLAN.md)의 전체 구현 목표는 진행 중이다. 아래 구현 기록을 전체 계획 완료로 해석하지 않는다.

## 장면·대표 페이지 차수

새 장면 12종을 실제 자식 노드로 구현했다. 영상 히어로·영상/본문 분할·영상 노트·오디오 에피소드, 사진 포트폴리오·사진/목차·전후 비교·정보 지점 룩북, 타이포 선언·사진 콜라주·레트로 노트·모듈 보드다. 제목·본문·사진·영상·버튼을 각각 선택해 수정·이동·삭제할 수 있다. 콜라주 사진은 개별 좌표·크기·회전과 화면별 배치를 갖는다. 기능 컴포넌트 안에서는 기존 Ctrl/⌘+클릭과 내부 목록으로 더 작은 부분을 편집한다.

T01~T08 팩마다 권장 장면 3개를 조합한 대표 페이지와 실제 화면 썸네일을 추가했다. 라이브러리의 `장면` 분류, 새 프로젝트의 팩 프리셋, 디자인 팩 창의 `대표 장면 보기`에서 찾을 수 있다. 대표 페이지 확인은 현재 문서를 바꾸지 않는다. 전체 정의는 225개, 페이지 루트를 제외한 삽입 항목은 224개, 시작 프리셋은 25개다. 장면은 조합 블록이며 신규 독립 기능 수에 합산하지 않는다.

직접 생성한 공간 사진 2장·제품 사진 1장과 자체 제작 6초 무음 WebM·12초 WAV·설명 자막을 포함했다. 이미지 원본·프롬프트는 `public/studio-assets`와 `docs/SCENE_IMAGE_PROMPTS.json`에 보존한다. 파일은 알려진 샘플 ID에 한해서 처음 사용할 때 가져오고, 크기·SHA-256을 검사한 뒤 일반 업로드와 같은 저장소에 보관한다. 알 수 없는 사용자 파일은 샘플로 대체하지 않는다. 동시에 여러 미리보기가 요청해도 파일별 다운로드를 공유한다. ZIP에 실제 원본이 들어가므로 다른 브라우저에서는 샘플 서버에 접근하지 않고도 복원할 수 있다.

레시피가 화면별 배치·외형·내부 스타일·구조화 목록·장면 안의 이름 있는 대상 연결을 지정할 수 있도록 확장했다. 챕터 대상과 버튼 링크는 실제로 생성한 자식 ID에 연결한다. 복제·붙여넣기는 내부 링크를 복제된 자식으로 바꾸며, 페이지 추가는 필요한 자산 메타데이터를 함께 병합한다. 검수에서 색 카드 라벨의 대비를 수정했다.

현재 범위의 한계: 사진 포트폴리오는 높이가 다른 열을 조합한 장면이며 일반 갤러리의 자동 masonry 기능은 아니다. 타이포 장면은 기존 등장 효과를 사용하며 새 단어별 모션은 아직 아니다. 기본 영상·오디오 재생 막대는 브라우저가 제공하므로 그 내부 버튼의 외형을 개별 편집하지 못한다. 팩 공통 테마는 프로젝트 단위다. 새 장면 추가나 페이지 추가가 기존 프로젝트의 테마를 자동으로 바꾸지는 않는다.

다음 차수는 기본 모션의 속도·지연·강도·반복·모바일 정지, 실제 단어별 등장, 이름 있는 슬롯과 내부 구조 해체, 자유로운 크기·그리드·상태 외형, 나머지 팩·기능·장면이다. 원래 계획의 16팩·20신규 기능·24장면·12추가 모션·12기존 개선 목표와 실기기·외부 재현 검증은 계속 남겨 둔다.

검증: 단위 **46/46**, TypeScript를 포함한 최종 정적 빌드, `lint:studio`, diff 공백 검사 통과. 첫 정적 전체 회귀는 **219/222**였다. WebKit에서 동시에 표시되는 오디오·영상 오류를 구분하지 않은 검사, 지연 로딩 이미지가 나타나기 전에 목록을 수집한 검사, ZIP 비동기 복원이 끝나기 전에 이미지를 판정한 검사를 실제 대상·완료 상태에 맞게 고쳤다. 최종 필터 분리·정지 썸네일을 포함해 다시 빌드한 뒤 새 장면, 수정한 미디어 오류 확인, 라이브러리 직접 삽입/Undo, 긴 한국어·영문과 움직임 감소, ZIP 복원을 **42/42** 재검사했다. 확인한 고유 브라우저 시나리오는 **228개(엔진당 76개)**다. 모든 228개를 한 번의 최종 실행으로 통과했다고 주장하지 않는다.

첫 8팩의 3개 핵심 장면씩을 390·768·1440px에서 검사하고 실제 썸네일을 눈으로 확인했다. 별도 긴 문구 검사도 같은 8팩·세 폭·세 엔진에서 수행했다. ZIP 원본의 바이트 검증 및 새 브라우저에서 샘플 URL을 차단한 복원을 확인했다. 상세 로그는 `artifacts/scene-e2e.log`, `artifacts/scene-final-e2e.log`; 최종 시각 자료는 `public/template-previews/pack-*.png`다. 이번 차수에서 입력 성능을 다시 측정하지 않았으며 위·아래 차수의 기존 성능 결과를 새 측정으로 제시하지 않는다. 실제 iOS/Android 및 네이티브 Safari 미디어 코덱 검증은 남아 있다.

## 현재 구현

- **문서 v5 / 원본 보존:** v2·v3·v4 읽기 변환, 첫 저장 시 이전 원본 체크포인트를 같은 트랜잭션에 보존한다. 자동 배치·자유 배치·기존 부분 경로·역할 경로·반복 표·200노드 문서의 고정 v4 자료 6개를 추가했다.
- **자산:** 이미지·영상·음성·WOFF2·VTT의 파일 시그니처 검사, SHA-256 기반 중복 제거, 브라우저 저장, 파일 교체, 누락 파일 재등록, 설명·출처·사용 횟수, 미사용 항목 제거와 Undo. 이미지/폰트 10MB, 영상/음성 50MB, VTT 1MB, 문서 자산 300개/150MB 제한이다. 실제 브라우저의 저장 공간은 별도이며 실패 시 원본 연결을 유지한다.
- **원본 수명:** 저장소는 플랫폼별 Blob 저장 차이를 피하기 위해 ArrayBuffer와 MIME을 보관하고 읽을 때 Blob을 만든다. 사용 중인 URL은 렌더러가 소유·해제한다. 목록에서 제거해도 다른 프로젝트·버전·복구본·Undo가 필요한 원본은 삭제하지 않는다. 전체 저장 공간 정리 기능은 아직 없다.
- **이동:** 프로젝트 ZIP에 문서·자산 manifest·원본을 포함하고 새 브라우저에서 복원한다. 압축 파일의 경로·중복·총 크기·엔트리 수를 사전 검사하고 실제 해제량을 제한한다. 누락/손상 원본을 성공한 백업처럼 표시하지 않는다. JSON/공유 링크에는 로컬 원본이 포함되지 않는다는 안내를 제공한다.
- **신규 기능 5종:** 영상, 오디오, 사진 확대 보기, 이미지 비교, 이미지 설명 지점. 기존 정의 205개에 추가되어 210개(삽입 가능 209개)다. 실제 미디어 재생, VTT·대본, 구간, 자동 음소거 시도, 화면 밖/백그라운드 정지, 편집·PNG의 포스터를 지원한다. 코덱/네트워크 실패에서도 편집할 수 있다.
- **구조화 항목:** `node.content`의 고유 항목 ID와 `values`를 사용한다. 갤러리를 사용자가 항목별 편집으로 전환하면 기존 문구·스타일을 옮긴다. 사진 교체·추가·삭제·복제·순서 변경, 안정적 내부 역할, 직접 문구 편집을 지원한다. 순서를 바꿔도 항목의 스타일과 파일 연결을 보존한다.
- **서체:** 제목/본문의 기본 서체와 업로드 서체를 분리한다. 동일한 WOFF2 원본을 렌더러·PNG·ZIP의 CSS·디자인 토큰에서 사용한다.

## 검증 기록

- 단위 검사 31/31, TypeScript, `lint:studio`, 정적 프로덕션 빌드 통과.
- Edge·Firefox·WebKit의 신규 자산·이미지 기능과 기존 복구 검사 **48/48** 통과. 정적 산출물 전체 실행(147 통과, 6 실패)에서 새 슬라이더/자산 탭 때문에 오래된 선택자가 실패했다. 검사 대상을 명시한 뒤 6개 모두 재검사 통과했고, 항목 편집 3개도 재확인했다. 합계 **153개 고유 기능·접근성 시나리오**를 확인했다.
- 자산을 넣은 상태의 추가 접근성·URL 수명 검사 **3/3** 통과. 내부 요소 목록의 작은 보조 글자 대비를 개선했다. 편집/미리보기 6회 왕복에서 보유 URL 수가 2→1→2로 유지되고, 프로젝트를 닫으면 0으로 해제됐다. 전체 기능·접근성 확인 범위는 **156개(엔진당 52개)**다. 이 URL 수 검사는 전체 브라우저 힙 메모리 측정을 대신하지 않는다.
- 실제 WAV/WebM 재생은 Windows Edge·Firefox에서 확인했다. Windows Playwright WebKit은 별도 기본 미디어 요소에서도 `MEDIA_ERR_SRC_NOT_SUPPORTED`를 반환했다. 이 환경에서는 원본 저장·복원과 코덱 미지원 대체를 검사하며 실제 Safari 디코딩 성공이라고 주장하지 않는다. 재현 스크립트: `scripts/diagnose-media.ts`.
- 갤러리 순서 변경 뒤 원본·문구·색상 보존, 확대 보기의 Escape·포커스 복원, 모바일 모달, range/설명 지점 키보드 조작, axe 검사를 수행했다. Firefox/WebKit에서 발견한 모달 포커스 복원 시점 문제를 고쳤다.
- 고정 v4 자료는 구조 보존 기준이다. 이전 릴리스의 픽셀 결과를 소급 재현한 자료는 아니다.
- 입력 성능(정적 산출물, 200노드/50행, 20개 표본, 작업자 1개, trace 꺼짐): Edge p95 **28.1ms**, Firefox **42ms**, WebKit 첫 측정 **102ms**. WebKit 단독 3회 추가 측정은 **102/91/91ms**이며 DOM p95는 **23/21/20ms**였다. WebKit의 100ms 미만 목표는 일관되게 통과하지 못했으며 미해결로 남긴다. 기능 검사의 성공으로 성능 기준을 통과했다고 간주하지 않는다. 결과는 `artifacts/performance-foundation-webkit-first.json`과 `artifacts/performance-desktop-webkit-repeat-*.json`에 보존했다.

## 이어서 구현할 때의 주의점

- 기존 v4 정의는 새 필드를 자동 주입하지 않는다. 새 v5 필드가 추가되어도 고정 v4 자료의 nodes/theme/pages 비교가 그대로 통과해야 한다.
- 레거시 갤러리는 명시적으로 항목 편집에 전환할 때만 구조화한다. `node.content.items`가 있으면 기존 `props.items`보다 우선한다. 100개 초과 목록은 원문을 유지하고 전환을 막는다. 기존 부분 경로의 문구는 항목 값으로, 스타일은 항목 역할로 옮긴다.
- `NodeContent`의 재사용 비교와 `ComponentParts`의 효과가 `node.content` 변경을 포함해야 한다. 직접 문구 수정은 `data-content-key/item/field`를 통해 원본 값과 연결된다.
- 기존 layout은 기본값도 명시적으로 채워져 있다. 값이 있다는 이유만으로 사용자 수정이라고 추정하거나 테마 적용 시 배치 전체를 초기화하지 않는다. 팩 일부 적용과 개별 값 보존을 별도 명령/검사로 다룬다.
- 현재 모션은 CSS의 개별 translate/scale/rotate와 layout의 transform을 조합한다. 확장 전에는 iframe 스크롤 기준, 개별 opacity 보존, 모션과 드래그 좌표 분리, 재생/정지 시 위치 복원을 실험해야 한다.
- 무거운 런타임은 아직 추가하지 않았다. 기존 라이선스 조사에 따라 GSAP/React Bits를 무조건 의존성으로 넣지 않는다. 실제 사용된 장면에서만 런타임/자산을 요청하도록 검증한다.
